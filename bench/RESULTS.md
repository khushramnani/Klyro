## Real agents (2026-11-18)

Claude Sonnet as the agent, one run per task and setup, given a plain-language task and the
tool's own guide only: `skill/SKILL.md` for klyro, agent-browser's bundled
`agent-browser skills get core` for agent-browser. Both drove the same installed Chrome.
"Agent tokens" is the agent's whole run (it includes the agent's fixed prompt and reading the
guide), as reported by the harness.

| task | agent-browser | klyro chromium | klyro router |
|---|---|---|---|
| Shop (saucedemo): log in, add the Bolt T-Shirt, report cart item and price | ok: 9 commands, 69.7k tokens, 28 s | ok: 8, 65.3k, 83 s | ok: 9, 65.4k, 34 s |
| Docs (Rust book): find Hello World, report the compile command | ok: 6 (one `find text` miss), 69.1k, 32 s | ok: 5, 64.5k, 23 s | ok: 5, 64.6k, 28 s |
| Local app: log in, type a note, screenshot it, check the image | ok: 8, 70.3k, 31 s | ok: 8, 66.3k, 26 s | ok: 7, 66.3k, 29 s |
| **Total** | **3/3, 209.1k tokens** | **3/3, 196.1k** | **3/3, 196.3k** |

All 9 runs answered correctly ($15.99; `rustc main.rs`; the screenshot showed the typed note,
checked by hand). On the router, the screenshot moved the session from Lightpanda to Chromium
and the typed note came along. Klyro used about 6% fewer agent tokens; part of that is the
shorter guide (SKILL.md is about 1.3k tokens, agent-browser's core skill about 4k).
Three runs per setup is a small sample: it says the agents succeed, not by how much.

## Across runs (2026-11-18)

Single scripted runs are noisy on the development machine (7.7 GB RAM, about 1 GB free): a step
can read a page that has not finished updating. Over the three full runs after the Task 14
fixes:

| setup | tasks finished |
|---|---|
| agent-browser | 22/30 (8, 8, 6) |
| klyro chromium | 29/30 (10, 10, 9) |
| klyro router | 30/30 (10, 10, 10) |

The Checkpoint E bar held in all three runs. Fixes made during Task 14, found by the first run:
action results on a new page print an outline (refs, headings, alert/status messages) instead
of the full tree; the router recovers when the fast lane crashes mid-step (it falls back to the
last known URL); the docs task now expects the Rust book's current wording.
